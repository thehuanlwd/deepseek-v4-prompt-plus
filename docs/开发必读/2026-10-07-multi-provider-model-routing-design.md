# 多供应商模型路由设计规格

> 版本：v1 ｜ 日期：2026-10-07 ｜ 适用版本：DSPlus 0.2.4+

## 1. 背景与目标

改造前：`config.json` 可以保存多个供应商，但同一时刻只有一个「当前对外供应商」生效；请求进来不读模型名，一律转发给它，模型清单接口也只回该供应商的清单。

改造后：同一个本地端口同时对接多个供应商，按请求中的模型名自动路由到对应供应商。供应商列表第一位为默认供应商（路由未命中时的兜底目标）。

明确不做（产品决策，勿擅自扩展）：故障切换、权重与负载均衡、模型别名映射（对外 A / 上游 B）、模型列表拖拽排序。

## 2. 数据模型

### 2.1 Provider 新增字段

| 字段 | 类型 | 语义 |
|------|------|------|
| `id` | string | 供应商唯一标识。模型 ID 跨供应商重名时作为对外前缀，对外模型名 = `供应商ID/模型ID`。字符白名单 `[A-Za-z0-9_-]`，允许纯数字，禁止 `/`（它是前缀分隔符，出现即导致解析歧义），比较时不区分大小写 |
| `enabled` | bool \| null | 是否参与路由。`null` / 缺省视为启用（旧配置兼容）；列表第一位（默认供应商）强制启用 |

`active_provider` 保留为兼容字段：仅与列表第一位名称保持同步，不再作为路由依据；前端提交的该字段被忽略。

现有 `name` / `base_url` / `anthropic_base_url` / `api_key` / `models` 字段语义不变，`name` 改名不影响 `id`。

### 2.2 排序语义

数组顺序即语义：**第一位 = 默认供应商 = 路由未命中的兜底目标 = 冲突裁决的优先方**。
不再依赖 `active_provider` 字符串匹配，因此供应商同名不会再造成静默命中错误项。

## 3. 路由规则

### 3.1 路由表构建（`route.go` 的 `buildRouteTable`，纯函数）

1. **参与范围**：已启用 **且** 配置了模型清单的供应商。同一供应商内的重复模型 ID 只计一次（后者不产生独立条目）。
2. **冲突统计**：统计每个模型 ID 被多少个供应商提供。
   - 唯一 → 对外名 = 原模型 ID
   - 重复 → 所有重复项统一加前缀，对外名 = `供应商ID/模型ID`
3. **二次冲突裁决**：若加前缀后仍与他人重名（例如某供应商原生模型名恰好等于另一供应商的「前缀 + 模型名」），保留列表顺序靠前者，其余标记为「无法路由」——不对外暴露、不可请求。

模型清单为空（穿透模式）的供应商：处于第一位时不参与合并与冲突判定，但仍是全能透传的兜底目标；处于其他位置时不参与路由表，界面提示「未配置模型清单，不参与路由」。

### 3.2 请求解析（`RouteTable.Resolve`）

匹配顺序：

1. 对外模型名**精确匹配**（模型 ID 大小写敏感，由上游决定）；
2. **供应商 ID 前缀剥离匹配**：前缀按 ID 长度降序尝试（避免短 ID 抢占长 ID），比较不区分大小写；剥离后的剩余部分整体作为模型名在该供应商内查找——因此模型名本身含 `/` 不会被误拆；
3. 未命中 → **回退默认供应商，模型名原样透传**。

命中后的处理要点：

- 请求体 `model` 字段被改写为**上游真实模型名**（已剥离前缀），且改写发生在 `json.Unmarshal` 之后、提示词重组 / 参数注入 / 请求审计之前，使后续环节看到的都是最终生效值。
- `originalBody` 保留客户端原始请求，用于语义类型检测与日志。
- 鉴权密钥与基础地址取本次命中的供应商（密钥为空时回退全局 `api_key`）；Anthropic 格式仍按 `anthropic_base_url` 优先解析。

### 3.3 模型清单接口（`GET /v1/models` 与 `/models`）

合并输出所有**可路由**模型（跳过「无法路由」项），`owned_by` 优先取模型分组，缺省取供应商名称。合并结果为空时保持原有穿透行为（转发上游）。

## 4. 界面行为（YoRHa 寄叶规范）

| 位置 | 行为 |
|------|------|
| 模型服务页 · 供应商列表 | 支持拖拽排序（拖拽期间暂停自动保存，落位后统一提交一次，避免顺序抖动）；第一位带「默认」直角标签且启用开关置灰不可关；其余为多选启用开关；徽标显示「已启用 N / 共 M」 |
| 模型服务页 · 供应商配置 | 名称与 ID 同行输入（名称前、ID 后），ID 实时校验字符与全局唯一性，非法值不写回数据 |
| 模型服务页 · 模型路由管理 | 卡片三行信息：显示名（带状态徽标）、对外模型 ID（冲突前缀高亮为橘红）、归属供应商与上游模型名；徽标取值：已加前缀 / 无法路由 / 未启用；顶部冲突汇总条 |
| 模型服务页 · 穿透横幅 | 默认供应商未配置清单 → 「穿透模式激活中（默认供应商）」；其他供应商未配置清单 → 「未配置模型清单，不参与路由」 |
| 设置页 | 移除「当前供应商」下拉与供应商增删按钮，改为默认供应商只读说明 + 跳转入口；供应商编辑区固定编辑第一位（默认供应商） |

冲突状态由后端 `GET /api/route/preview` 提供，前端不重复实现冲突计算，避免规则漂移。

## 5. 迁移与兼容

1. **旧配置无 `id`**：加载时自动补生成——名称合法（字母 / 数字 / 下划线 / 短横线）取同名，否则按 `provider1`、`provider2` 顺序生成，重复自动加序号；补生成结果落盘。
2. **旧配置的 `active_provider` 指向的供应商不在首位**：一次性上移到首位（仅当首位供应商还没有 `id` 时执行），使用户原先选定的供应商继续作为默认供应商；用户拖拽排序后不会被旧字段拉回。
3. **旧配置无 `enabled`**：视为启用。
4. **缺失 / 非法 / 重复的 ID 在保存时由服务端规范化兜底**，并通过响应 `warnings` 字段提示前端展示。

## 6. 边界与已知取舍

- **对外模型名是动态计算的**：冲突加前缀按当前配置实时计算。供应商增删、启用开关、模型清单变化都会改变对外模型名，客户端已固化的模型名可能失效，需重新拉取模型清单。此代价随「按模型路由」方案固有。
- **默认供应商的兜底是原样透传**：未命中路由表的模型会带着客户端原始名称发给默认供应商，上游不认识时报错属预期行为。
- **模型 ID 大小写敏感、供应商 ID 大小写不敏感**：前者由上游决定，后者只用于前缀匹配与去重。
- **路由表不缓存**：每次请求现算（O(供应商数 × 模型数) 字符串比较，相对一次 HTTP 转发可忽略），保证配置变更立即生效；若后续规模显著增长，只需在 `SafeConfig` 内加版本号缓存，纯函数签名不变。
- **`enabled` 必须用 `*bool`**：Go 的 bool 零值是 `false`，用 `bool` 会让旧配置加载后全部变成「未启用」，升级即全线失效。

## 7. 关键实现位置

| 文件 | 职责 |
|------|------|
| `config.go` | `Provider.ID` / `Provider.Enabled` / `IsEnabled()` / `normalizeProviderIDs()` / `normalizeProviders()` / 加载迁移 / 落盘前防止密钥二次加密 |
| `route.go` | `buildRouteTable()` / `RouteTable.Resolve()` / `ListModels()` / `Stats()` / `DefaultProvider()` |
| `proxy.go` | 请求分发与模型名改写、模型清单合并、`defaultProvider()` / `ctxUpstream()` / `providerAPIKey()` |
| `retry.go` | 防循环重试与分析子Agent按本次请求命中的供应商转发 |
| `gui.go` | `POST /api/config` 解析 `id` / `enabled` 并规范化；`GET /api/route/preview` 路由表预览 |
| `web/app_v2.js` | 拖拽排序、多选启用开关、ID 编辑与校验、冲突徽标与汇总条 |
